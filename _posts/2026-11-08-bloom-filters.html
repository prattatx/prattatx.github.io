A Bloom filter tells you, in very little memory, that an item is definitely not in a set or possibly in it. Burton Bloom described it in 1970, and it still sits in front of slow lookups in caches and databases. Here it is four ways: plain text, diagrams, a calculator you can change and a short narrated video. Start with whichever suits you.

Figure 1. How an item moves through the filter. Adding and checking use the same k positions. That is why a "no" is always right and a "yes" is only possibly right.

How a Bloom filter works

A Bloom filter tells you if an item is possibly in a set. It uses a row of bits and a few hash functions. It never gives a false "no". It can give a false "yes".

Caution: you cannot remove an item from a standard Bloom filter. If you set a bit back to 0, other items can become false negatives.

  1. Make a row of m bits. Set all the bits to 0.
  2. Select k hash functions. Each function changes an item into one bit position.
  3. To add an item, calculate its k positions.
  4. Set the bit at each of those positions to 1.
  5. To query an item, calculate its k positions again.
  6. Look at the bits at those positions.
  7. If one bit is 0, the item is not in the set.
  8. If all the bits are 1, the item is possibly in the set.

Two different items can share bit positions. Thus, an item that you did not add can find only 1s. That result is a false positive. More bits per item make false positives less frequent.

The core idea, from loose to strict plain English

The check, drawn

The check is the part people get wrong, because "yes" and "no" are not equally sure. As text: to check an item, the filter runs it through the same k hash functions that it used to add items. It reads the bit at each of the k positions. If any of those bits is 0, the item was never added, because adding it would have set that bit. If all of them are 1, the item is possibly in the set: the bits could also have been set by other items.

Figure 2. The check as a diagram. Only one of the two answers is a guarantee.

Size a filter

How often the filter says "possibly" for an item you never added depends on two choices: bits per item and the number of hash functions. Change them and watch the false positive rate and the memory.

When to use one

Put a Bloom filter in front of a lookup that is slow or expensive. Every "no" skips that lookup for certain. Every "possibly" still goes to the lookup, so a false positive costs one extra check and never a wrong answer.

Size it before you build it: about 10 bits per item keeps false positives under 1%.

Source: Burton H. Bloom, "Space/Time Trade-offs in Hash Coding with Allowable Errors", Communications of the ACM 13(7), 1970. The words and bit positions in the video and diagrams are illustrations.
