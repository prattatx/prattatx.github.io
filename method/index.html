Approach / Function allocation

How I decide who does what

When a team adds AI to a job, someone has to decide which tasks the machine takes and how much it decides on its own. Human factors calls that decision function allocation, and it has a method. This is the one I use.

1. Watch the work

List every task

I start by watching people do the job with the tools they have, and then I ask them about what I saw. People can show a judgment call that they could never have described in a meeting, so observation finds tasks that no requirements document lists.

The methods are naturalistic observation, stimulated recall and probing. The output is a complete list of the tasks in the job.

2. Score each task

Choose a level of automation

For each task the question is how much of the decision the machine should hold. Thomas Sheridan's levels of automation, first set out for the supervisory control of complex systems, give that question a scale.

  1. 1Person does itJudge the exception
  2. 2Machine suggestsWrite the reply
  3. 3Machine acts, person approvesCheck the record
  4. 4Machine acts, person is toldRead the request
  5. 5Machine does itFile the result

Five stops on the scale, each with an example task from a job that answers customer requests.

I score each task against four things: what it costs if the result is wrong, whether it can be undone, how often the task comes up, and who answers for it.

I first did this work in 2002 at Lockheed Martin, on a Navy destroyer program. The question there was which jobs on the ship the machines should take and which had to stay with the crew. That work cut the mission center crew by more than half.

3. Write it down

A table the team can use

The result is a table: each task, its level, and the reason. It goes into the specifications and prompts the team already works from, so the people who run the system can follow it and can argue with it.
