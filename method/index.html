Approach / Function allocation

How we decide who does what

When a team adds AI to a job, someone has to decide which tasks the machine takes and how much it decides on its own. Human factors calls that decision function allocation, and it has a method. This is how the teams I have led do it.

1. Watch the work

List every task

We start by watching people do the job with the tools they have, and then we ask them about what we saw. People can show a judgment call that they could never have described in a meeting, so observation finds tasks that no requirements document lists.

The methods are naturalistic observation, stimulated recall and probing. The output is a complete list of the tasks in the job.

2. Score each task

Choose a level of automation

For each task the question is how much of the decision the machine should hold. Thomas Sheridan's levels of automation, first set out for the supervisory control of complex systems, give that question a scale.

We score each task against four questions, and the answers set its level.

3. Write it down

A table the team can use

The result is a table: each task, its level, and the reason. It goes into the specifications and prompts the team already works from, so the people who run the system can follow it and can argue with it.

Where this comes from

A Navy destroyer program, 2002

I first led this work in 2002 at Lockheed Martin, on the U.S. Navy's next-generation destroyer program. The question there was which jobs on the ship the machines should take and which had to stay with the crew.

We modeled the operators' workload, kept it inside a safe band, and moved the tasks that freed up to early automation.
